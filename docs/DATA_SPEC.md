# 数据与证据约定

## 三种证据状态

- `single_source_checked`：取得日线并通过本项目的结构与日期校验，可复算指标；没有独立第二来源验证。
- `legacy_unverified`：只有旧版汇总快照，可重新汇总，不能验证原始指标与历史行情。
- 数据不可用：无有效样本时保留异常报告，CLI返回非零退出码，不伪造一个平稳市场。

所有输出中的 `independently_verified` 当前均为false，`publish_ready` 也为false。后者是机器可读的发布门槛，不是要求每次人工操作必须经过额外审批；它防止未经独立核验的结果自动标成认证行情。

## 字段和单位

| 字段 | 定义 / 校验 |
|---|---|
| 日期 | 可解析、无重复；仅选择研究日及此前18个月 |
| 开、高、低、收 | 数值有限且为正；最高不小于开收低、最低不大于开收高 |
| 动态结算价 | 前一条日线有效正值才参与涨跌幅 |
| 持仓量 | 非负有限值；今昨齐全才计算差值 |
| 合约乘数 | 从规则表按代码匹配；缺失停止仓位测算 |
| 保证金比例 | 规则表百分数，如14代表14%；未知不显示0 |
| MA10 | 对应周期的10期简单平均 |
| ATR14 | 前收盘口径，最近14根TR的简单平均 |
| 金额 | 人民币元；连续价格单位与对应品种乘数配合使用 |

非正价格被拒绝属于当前适用范围约束，不代表所有期货市场都不可能有负价格。特殊市场情形须重新定义验证规则。

## 时间的区别

研究交易日由 `--date` 指定；默认是上海自然日，不是自动推断的交易日。采集时间、报告生成时间、账户查询时间分别记录。运行历史报告时，账户数据只显示为当前查询状态，不能暗示它属于历史日。

本版未接入交易所日历、完整交易时段判断或最终结算确认，用户应在数据已更新后运行盘后报告。周月K线含当前未结束周期；前一条日线不保证中间没有缺失交易日。

## 原始档案

`raw/<run_id>/` 每次运行独立建目录，包含接口返回的CSV与 `manifest.json`。这是 AkShare 返回表的归档，并非 HTTP 原始报文。

manifest记录请求日期、历史起点、品种清单、接口来源、每个请求起止时间、失败项、软件版本、代码文件哈希和输入文件SHA256。规则表来源为期货公司日历页面；实际返回内容是否严格对应请求日期尚未独立验证。

离线重放检查路径和SHA256，防止无意中拿另一个版本的数据重算。哈希不保证源站数据真实，也不能对抗档案和清单同时被修改。

账户查询响应不保存进公共原始档案。实时产物和raw目录默认被gitignore忽略。

## 缺失与降级

不存在研究日的数据，排除该品种并在正文列出原因；不使用旧日价格凑齐覆盖数。前结算价未知时保留均线分类但退出涨跌统计。历史不足为无法判断，不等同于不共振。规则获取失败时行情分析仍可继续，手数未知。

采集子进程有单接口超时，不进行无限重试。错误详情保存在manifest，报告列出受影响品种。部分样本可生成研究报告，但不得把子样本的市场温度写成完整市场结论。

## 复算与独立验证

重放命令：`python daily_report.py --replay raw/<run_id>/manifest.json`。

复算要比较未四舍五入的指标和分类，展示值只用于阅读。独立核验必须先对齐实际合约、交易日、收盘/结算字段和单位；两个网站都转引新浪，不构成真正独立来源。当前没有自动第二来源核验，也没有自动主力合约映射。
